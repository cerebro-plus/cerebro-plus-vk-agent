# Структура короткого HTML-отчёта

## 1. Объём и компоновка

Собрать один автономный адаптивный HTML без внешних библиотек, шрифтов и сетевых ресурсов. Использовать светлый фон, один акцентный цвет и вертикальную структуру смысловых блоков. Отчёт должен занимать 1–2 страницы при печати на A4; ориентир — 450–1600 видимых слов и компактный печатный CSS.

В начале написать:

> На этой неделе ваши конкуренты выпустили N постов.

Затем указать число пригодных для относительного ER постов, размер квартиля, количество неранжируемых постов и фактически использованные типы конкурентов. Это вводный текст, а не аналитический буллит.

## 2. Обязательные разделы

1. `Топ-25% с лучшим ER относительно среднего ER сообщества`
2. `Топ-25% с худшим ER относительно среднего ER сообщества`
3. `Что видно по комментариям и клипам`
4. `Общий вывод`

В верхнем и нижнем квартилях обязательно раскрыть:

- какие посты вошли в квартиль;
- форматы;
- темы;
- CTA;
- реакции;
- вложения.

В блоке комментариев и клипов раскрыть:

- о чём аудитория пишет и спрашивает;
- какие триггеры подтверждены комментариями;
- какие обещания и результаты используются;
- какие аргументы применяются: цифры, кейсы, отзывы, демонстрации, сравнения;
- какие визуалы и элементы оформления используются;
- какой тон и сценарные приёмы используются;
- какие хуки и первые секунды используются в клипах.

В общем выводе отдельно показать:

- актуальные сейчас форматы, темы и CTA;
- неактуальные сейчас форматы, темы и CTA.

## 3. Аналитический буллит

Каждый самостоятельный вывод — один элемент:

```html
<li class="analysis-bullet" data-finding-id="top-formats-video">
  <strong>Форматы.</strong>
  Короткий вывод простыми словами.
  <div class="quote-row">«Короткая точная цитата»</div>
  <div class="post-example">
    <strong>Пост-пример:</strong>
    <a href="https://vk.com/wall-1_1" target="_blank" rel="noopener">-1_1</a>
  </div>
</li>
```

Требования:

- внутри каждого `li.analysis-bullet` находится ровно один `div.post-example`;
- внутри `div.post-example` находится хотя бы одна прямая VK-ссылка;
- строка содержит ссылки на все `evidence_post_ids` буллита;
- ссылки других буллитов не объединяются;
- блоки доказательств не размещаются вне аналитических буллитов;
- при нескольких форматах, темах, CTA или цитатах создавать несколько буллитов, а не одну строку с перечислением через запятую.
- один буллит должен содержать один короткий вывод: не более двух предложений и не более двух запятых в `analysis`;
- не использовать шаблонные обороты «следует отметить», «важно отметить», «можно сделать вывод», «в рамках данного», «ключевой инсайт».

## 4. Цифры

Постовые ER, бенчмарк и отношение показывать только для постов, у которых:

```text
relative_er >= 2
или
relative_er <= 0.5
```

Для остальных доказательств выводить только ссылку. Общие размеры выборки, квартилей и агрегаты комментариев разрешены независимо от этого правила.

## 5. Текст

- Использовать простые короткие предложения.
- Давать точные CTA и короткие цитаты.
- Не использовать канцелярские и шаблонные ИИ-формулировки.
- Не выдавать отсутствие публичной реакции за доказанный провал звонков, переходов или личных сообщений.
- Не добавлять рекомендации и отдельный список ссылок в конце.

## 6. Автоматическая проверка

Проверить:

- четыре раздела в точном порядке;
- наличие всех обязательных категорий;
- равенство числа `li.analysis-bullet` и `div.post-example`;
- ровно один `div.post-example` и хотя бы одну ссылку внутри каждого буллита;
- отсутствие блоков `post-example` вне буллитов;
- соответствие множества ссылок `evidence_post_ids` каждого вывода;
- формат каждой ссылки `https://vk.com/wall<post_id>` и наличие `post_id` в dataset;
- допустимый объём;
- отсутствие вручную написанных числовых ER и бенчмарков;
- наличие обязательных точных CTA и цитат из доступных источников;
- заполненную визуальную сверку XLSX, медиа и расшифровок;
- отсутствие рекомендаций, секретов и неизвестных `post_id`;
- SHA-256 для `analysis_input`, `comment-signals` и `report_findings`.
