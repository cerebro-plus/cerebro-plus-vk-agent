# Контракт анализа

## 1. Входная цепочка

Основной источник — подтверждённый `vk_posts_dataset.json`. JSON комментариев обязан содержать ровно то же множество строковых `post_id`. `final_validation.json` обязан подтверждать SHA-256 dataset, комментариев и XLSX.

Проверить:

- `ER = (likes + comments + reposts) / views`;
- при `views <= 0` значение `er` равно `null`;
- бенчмарк сообщества равен среднему валидных ER постов сообщества в том же окне;
- ссылка равна `https://vk.com/wall<post_id>`;
- все относительные медиапути существуют;
- каждый клип имеет `transcription_status: success` или `no_speech`;
- XLSX содержит обязательные листы;
- множество прямых ссылок `https://vk.com/wall<post_id>` в XLSX в точности совпадает с множеством ссылок dataset.

Не переносить в компактный аналитический вход токены, access key, подписанные URL и персональные VK ID авторов комментариев.

## 2. Относительный ER и квартили

Для каждого поста:

```text
rankable = er is not null and benchmark > 0
relative_er = er / benchmark, если rankable
metric_display_allowed = relative_er >= 2 or relative_er <= 0.5
```

Отсортировать пригодные посты по `relative_er` по убыванию. Размер верхнего и нижнего квартиля — `ceil(rankable_count × 0.25)`. Посты без ER или с нулевым бенчмарком не включать в квартиль, но учитывать в общем числе проверенных постов и явно называть их количество.

Высокий относительный ER означает только более сильную вовлечённость относительно обычного уровня сообщества. Он не доказывает интерес к содержанию, заявку, переход или покупку. При малом числе просмотров прямо указывать ограничение базы.

## 3. Приоритет конкурентов

Анализировать все проверенные посты. При подборе `evidence_post_ids` соблюдать порядок:

1. прямые конкуренты;
2. косвенные конкуренты, если прямых доказательств недостаточно;
3. конкуренты за внимание, если первых двух уровней недостаточно.

Не скрывать, какие уровни реально использованы. Не исключать посты из расчёта квартилей из-за типа конкурента.

Если `evidence_post_ids` содержит пост более низкого уровня, хотя в доступном наборе раздела есть посты более высокого уровня, заполнить `tier_escalation_reason`. Причина должна называть, каких релевантных данных не хватило: нужного формата, темы, CTA, комментария, визуала или клипа. Общая фраза «данных недостаточно» не подходит.

## 4. Комментарии и покупательские триггеры

Классы комментариев:

- `code_word` — короткий ответ на явную механику кодового слова;
- `low_content` — эмодзи или короткая общая реакция без предметного смысла;
- `substantive_commercial_question` — вопрос о цене, записи, наличии, месте или условиях;
- `substantive_topic_response` — опыт, аргумент, предметный вопрос или вклад по теме;
- `other` — реакция без надёжной классификации;
- `no_comments` — у поста нет собранных комментариев.

Покупательский триггер — глубинная мотивация или критерий выбора, явно раскрытый в содержательном комментарии. Текст поста, обещание автора, высокий ER, кодовое слово и эмодзи не подтверждают триггер.

Если комментариев нет, писать: аудитория ничего не спросила; содержательная реакция и покупательские мотивы не подтверждены. Не создавать цитаты комментариев.

## 5. CTA и причинность

Допустимые статусы:

- `observed_aligned` — CTA и согласованное публичное действие видны в выгрузке;
- `no_observed_public_action` — CTA просит публичное действие, но его нет;
- `off_platform_unobservable` — действие уходит в звонок, личные сообщения, форму или переход и не наблюдается в данных;
- `no_explicit_cta` — явного CTA нет.

Не писать «CTA вызвал», «CTA не работает» или равнозначную причинную формулировку без наблюдаемого согласованного действия. Для звонков, переходов, личных сообщений и заявок без аналитики использовать только формулировку «действие не наблюдается в выгрузке».

## 6. Контракт findings.json

```json
{
  "status": "draft",
  "title": "Что сработало у конкурентов во ВКонтакте за неделю",
  "summary": "Короткое описание выборки без рекомендаций",
  "sections": [
    {
      "id": "top_quartile",
      "findings": [
        {
          "finding_id": "top-formats-video",
          "category": "formats",
          "headline": "Форматы",
          "analysis": "Короткий вывод простыми словами.",
          "signal_types": ["descriptive"],
          "evidence_post_ids": ["-1_1"],
          "metric_post_ids": ["-1_1"],
          "comment_evidence_ids": [],
          "tier_escalation_reason": "У прямых конкурентов в квартиле нет клипов с расшифровкой.",
          "quotes": [
            {"post_id": "-1_1", "text": "Короткая точная цитата"}
          ]
        }
      ]
    }
  ]
}
```

Обязательный порядок разделов:

1. `top_quartile`
2. `bottom_quartile`
3. `audience_and_clips`
4. `overall`

Обязательные категории:

- `top_quartile`: `scope`, `formats`, `themes`, `cta`, `reactions`, `attachments`;
- `bottom_quartile`: `scope`, `formats`, `themes`, `cta`, `reactions`, `attachments`;
- `audience_and_clips`: `audience`, `triggers`, `promises`, `arguments`, `visuals`, `tone`, `hooks`;
- `overall`: `current`, `not_current`.

Можно создавать несколько выводов одной категории. Каждый вывод обязан иметь непустой `evidence_post_ids`. Все перечисленные доказательства выводятся в строке `Пост-пример` именно этого буллита.

`metric_post_ids` может содержать только доказательства этого вывода с `metric_display_allowed: true`. Для остальных постов HTML не показывает числовые ER и бенчмарки.

Цитата должна быть не длиннее 200 символов и дословно присутствовать в тексте поста, расшифровке или комментарии. Для `purchase_motivation` обязательны `comment_evidence_ids`.

В корне `findings.json` обязателен блок визуальной сверки:

```json
{
  "visual_review": {
    "xlsx_visual_check_passed": true,
    "xlsx_sheets_checked": ["Сводка", "Лучшие посты", "Проверенные посты", "Недоступно"],
    "media_visual_check_passed": true,
    "media_post_ids_checked": ["-1_1"],
    "transcripts_checked_post_ids": ["-1_2"]
  }
}
```

`media_post_ids_checked` обязан содержать все посты с локальными изображениями, коллажами или клипами. `transcripts_checked_post_ids` обязан содержать все клипы. Отсутствие подтверждения блокирует сборку.

Для категорий `cta`, `promises`, `arguments` и `hooks` требовать цитату, если у выбранных постов есть соответствующий текст или расшифровка. Если в выборке есть содержательные комментарии, категория `audience` обязана включать цитату комментария.

Не вписывать числовой ER, бенчмарк или отношение вручную в `summary`, `headline` и `analysis`. Использовать только `metric_post_ids`; генератор покажет цифры лишь для `relative_er >= 2` или `relative_er <= 0.5`.

## 7. Запрещённые выводы

- Причинность CTA без `observed_aligned`.
- Интерес к теме только из ER, кодовых слов или эмодзи.
- Покупательский триггер только из текста поста.
- Продажи, заявки или переходы без соответствующих данных.
- Рекомендации, советы, контент-планы и идеи будущих публикаций.
