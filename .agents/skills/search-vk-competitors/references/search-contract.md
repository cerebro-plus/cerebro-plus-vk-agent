# Контракт поиска и измерений

## Сбор пула

`collect` читает карточки версий 1.0 и 1.1, но принимает только `confirmed`.
Запросы идут в порядке: запросы карточки, названия известных и обязательных
проектов, сочетания основных продуктов, ниши, широких категорий и географии.
Каждый вызов `groups.search` использует `count=1000`; страницы проходят через
`offset`. После каждого содержательного запроса фиксируются размер пула, число
новых `group_id` и доля прироста.

Расширение останавливается после двух последовательных приростов ниже 5% либо
после достижения `3 × target_count`. Известные проекты и обязательные включения
с VK-ссылками разрешаются отдельно и добавляются независимо от точки остановки.

После объединения выполняются дедупликация по числовому `group_id`,
`groups.getById` пакетами и измеримые фильтры: доступность, тип сообщества,
подписчики и география. Все решения попадают в аудит.

## Смысловые пакеты

Прошедшие кандидаты получают воспроизводимый `rank_score`. Известные и
обязательные проекты имеют приоритет. Остальные ранжируются по совпадению
лексики карточки, запросов, географии, наличию сайта и диапазону подписчиков.

`collect` создаёт `review_batches/manifest.json` и последовательные
`batch-NNN.json` максимум по 200 кандидатов. В пакет попадают только компактная
карточка и обрезанные поля, необходимые для квалификации. Следующий пакет
открывается только когда `review-status` сообщает его номер.

## Публикации и ER

`measure` вызывает `wall.get` только для кандидатов с `decision=include`.
Используется `count=100`, `offset` увеличивается до конца стены или страницы, на
которой все обычные собственные посты старше начала собираемого окна.
Закреплённые посты не участвуют в решении об остановке. Дубли удаляются по
`owner_id + post_id`.

Окно ER всегда равно `31 × 24 = 744` часа и едино для всех сообществ. Критерий
свежести карточки применяется отдельно к последней собственной публикации.
Скрипт при необходимости проходит более глубокое из двух окон.

`ER = (likes + comments + reposts) / views` только при `views > 0`. Для
отсутствующих, нулевых и некорректных просмотров сохраняются соответственно
`missing_views`, `zero_views`, `invalid_views`. Средний ER считается по всем
измеримым собственным постам в окне.

## Финализация

Если цель не достигнута, но остались необработанные смысловые пакеты,
`finalize` останавливается. После исчерпания пула разрешён результат с фактическим
количеством без ослабления критериев. Все обнаруженные `group_id` обязаны
присутствовать в `candidate_audit.json`.

`validate` сверяет карточку и её SHA-256, происхождение промежуточных файлов,
ID, типы, источники, окно, ER, причины исключения, количество строк и значения
Excel, статусы и секреты.
